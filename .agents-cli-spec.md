# Agent Spec

## Overview
The Ambient Expense Agent is an event-driven, graph-based ADK 2.0 `Workflow` prototype (`ambient-expense-agent`) that automates employee expense claim processing. Incoming expense claims are routed deterministically based on their dollar amount:
- **Standard claims (`< $100.00` and `> $0.00`):** Routed to the `auto_approve` node, which automatically approves valid claims without invoking an LLM or requiring human intervention.
- **High-value claims (`>= $100.00`):** Routed to the `review_agent` node, which uses an LLM / structured review flow and triggers a human-in-the-loop pause via `RequestInput` (`google.adk.events.request_input.RequestInput`) so a human reviewer can approve or reject the expense before final disposition.

## Language
`python`

## Architecture & Sub-Agents
- **Root Agent (`root_agent`):** ADK 2.0 `Workflow` (`google.adk.workflow.Workflow`) configured with `ResumabilityConfig` in the ADK `App` to support human-in-the-loop pause and resume.
- **Graph Topology (Option 1 — Hybrid Rule Router + HITL Review):**
  1. `START` → `parse_expense_email` → `route_by_amount`: Parses incoming expense input (Pub/Sub trigger JSON, plain JSON, or text representation containing `amount`, `submitter`, `category`, `description`, `date`) and emits `Event(output=..., route=...)`:
     - Route `"AUTO_APPROVE"` when `amount < 100.0`.
     - Route `"NEEDS_REVIEW"` when `amount >= 100.0`.
  2. `auto_approve` node (`FunctionNode`): Deterministic Python node that approves claims under `$100.00`, logs the decision, and emits both `Event(content=...)` and `Event(output=...)`.
  3. `review_agent` node (`Agent`) → `request_approval` (`RequestInput`) → `process_decision`: Handles claims of `$100.00` or more. Analyzes risk factors, calls `emit_expense_alert`, and pauses execution via `RequestInput` (`google.adk.events.RequestInput`) for human sign-off before `process_decision` records the final approval or rejection.

## Example Use Cases
1. **Use Case 1 — Low-Value Claim Auto-Approval (`< $100`):**
   - **Input:** `{"amount": 45.00, "submitter": "bob@company.com", "category": "meals", "description": "Team lunch", "date": "2026-04-12"}`
   - **Expected Flow:** `START` → `parse_expense_email` → `route_by_amount` (`AUTO_APPROVE`) → `auto_approve`
   - **Expected Output:** Status `approved` automatically by `auto_approve` with no `RequestInput` interrupt emitted.
2. **Use Case 2 — High-Value Claim Human-in-the-Loop Pause (`>= $100`):**
   - **Input:** `{"amount": 250.00, "submitter": "alice@company.com", "category": "travel", "description": "Flight to NYC for client meeting", "date": "2026-04-10"}`
   - **Expected Flow:** `START` → `parse_expense_email` → `route_by_amount` (`NEEDS_REVIEW`) → `review_agent` → `request_approval`
   - **Expected Output (Initial Run):** Workflow pauses at `request_approval` by yielding `RequestInput` containing the expense details and asking for manager approval/rejection.
   - **Expected Output (Resumed Run with `"approve"`):** Workflow resumes at `process_decision` and outputs final status `approved` (or `rejected` if the human replies `"reject"`).
3. **Use Case 3 — Boundary Value (`$100.00` Exact):**
   - **Input:** `{"amount": 100.00, "submitter": "carol@company.com", "category": "software", "description": "Annual dev tool license", "date": "2026-04-12"}`
   - **Expected Flow:** `START` → `parse_expense_email` → `route_by_amount` (`NEEDS_REVIEW`) → `review_agent` → `request_approval` (triggers `RequestInput` pause).

## Tools Required
- **`emit_expense_alert`:** Structured logging tool used by `review_agent` to emit a `WARNING` alert entry when a claim of `$100` or more requires manager review.

## Constraints & Safety Rules
1. **Strict Threshold Enforcement:** Expenses with `amount >= 100.00` MUST NEVER be routed to `auto_approve` or approved without a human-in-the-loop `RequestInput` response.
2. **No Prompt Injection Override:** Because routing (`< $100` vs. `>= $100`) is enforced deterministically in Python code (`route_by_amount`) rather than by an LLM prompt, instructions inside an expense `description` cannot bypass `review_agent`.
3. **ADK 2.0 Compatibility:** Uses `google.adk.Workflow`, `google.adk.Event`, and `google.adk.events.RequestInput` with typed `ExpenseData` Pydantic `BaseModel` schema.

## Success Criteria
1. **Auto-Approval Accuracy (Pass/Fail):** 100% of valid test claims with `amount < 100` traverse the `auto_approve` node and finish with `status == "approved"` without emitting `RequestInput`.
2. **HITL Pause Accuracy (Pass/Fail):** 100% of test claims with `amount >= 100` traverse the `review_agent` node and emit a `RequestInput` event pausing execution until resumed.
3. **HITL Resume Accuracy (Pass/Fail):** Supplying an approval or rejection response on a paused `>= $100` session resumes `process_decision` and produces the matching final `approved` or `rejected` output.
4. **Evaluation Threshold:** `agents-cli eval run` passes all defined evaluation cases with a score of `>= 4.0` (out of 5).
